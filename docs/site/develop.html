04 / Build it yourself

Open the source.

Kotlin, Jetpack Compose, and Material 3. One Android module. Minimum SDK 26.

Build and install

Use JDK 17 and an Android SDK with platform 34 and build tools 34.0.0, matching the APK workflow. Clone the repository and open its root in a terminal.

git clone https://github.com/mrduhlol/stikr.git
cd stikr
./gradlew :app:assembleDebug
# Connect an Android phone with USB debugging enabled.
adb install app/build/outputs/apk/debug/app-debug.apk

You can also open the project in Android Studio and press Run.

Run tests and render screens

./gradlew testDebugUnitTest
./gradlew testDebugUnitTest --tests "com.stikr.app.ui.ScreenRenderTest"

Robolectric renders sample stickers into app/build/sticker-renders/. The screen test renders whole screens in light and dark, including dialogs, into app/build/ui-renders/. Committed screenshots live in docs/theme/; python3 docs/theme/make-screens.py (needs Pillow) rebuilds them from those renders.

Find the code

Paths under app/src/main/java/com/stikr/app/
FileResponsibility
render/StickerRenderer.ktDraws the final 512×512 sticker: dilated silhouette outline, subject, then caption.
render/StickerCodec.ktEncodes WebP and reduces quality until it fits WhatsApp's limits: 100 KB per sticker and 50 KB per tray icon.
editor/SubjectCutout.ktWraps ML Kit subject segmentation in a suspend function. Returns null when cut-out is unavailable.
data/PackRepository.ktStores files and pack.json in private app storage. No database. Parsed pack.json is cached until the file changes.
export/StickerPackContentProvider.ktImplements WhatsApp's sticker provider contract: metadata, stickers/<pack>, and stickers_asset/<pack>/<file>, readable only with com.whatsapp.sticker.READ.
ui/MainViewModel.ktEditor and pack state. Slider drags are conflated into one preview render at a time, reusing the outlined subject layer when only the caption changes.
ui/StickerImage.ktDecodes sticker thumbnails off the main thread at their displayed size, into a shared 8 MB memory cache.
ui/theme/Theme.kt and ui/neo/Neo.ktDefine the palette, typography, and shared component kit.

Build speed and startup

gradle.properties turns on the configuration cache, the build cache, and parallel execution, so repeat builds skip configuration and reuse task outputs. CI caches Gradle with gradle/actions/setup-gradle, runs the unit tests on pushes to main and release tags, and uploads their reports.

Release APKs bundle a baseline profile for launch and the home screen, app/src/main/baseline-prof.txt, which androidx.profileinstaller installs on sideloaded phones. Compose preview tooling ships in debug builds only.

Release a signed APK

Maintainers bump versionName and push a v* tag. The existing build-apk.yml workflow builds and signs with keystore/release.p12. It attaches stikr.v<version>.apk and the stable stikr.apk to the GitHub Release.

Pushes to main build a debug APK for smoke testing. Each CI runner uses a throwaway debug signing key, so those builds cannot update one another. Tagged releases use the persistent signing key and can update an installed release.

Work on these docs

The site is plain HTML and one CSS file in docs/site/. No build step, JavaScript, external fonts, or CDN is needed.

python3 -m http.server 8000 --directory docs/site

Open http://localhost:8000. Check narrow screens, keyboard navigation, and light and dark modes. After regenerating screenshots, copy docs/theme/screens-light.png and docs/theme/screens-dark.png to docs/site/assets/.

pages.yml deploys only docs/site/ on pushes to main. A repository administrator must select GitHub Actions as the Pages source in repository settings.
